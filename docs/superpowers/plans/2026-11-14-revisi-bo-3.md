# Revisi Back Office Putaran Ketiga Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Memenuhi seluruh dokumen "Revisi Penyesuain BO 2": Info barang empat riwayat, No Rekening dihapus dari Master, dan semua halaman Transaksi dibangun ulang sesuai gambar 8 sampai 13 dalam satu layar dengan isi terlihat.

**Architecture:** Komponen bersama di `src/apps/bo/screens/trx/` (kotak cari barang, dialog Rincian Barang, tabel baris, kepala sebaris, kerangka daftar) dipakai Faktur Penjualan, Faktur Pembelian, SO, dan PO. Logika hitung dan data riwayat berada di modul domain murni yang diuji unit. Teks baru ada di modul teks malas, bukan `src/shared/labels`.

**Tech Stack:** TypeScript murni, Vite 8, Vitest 5, Playwright 1.64 (`channel: 'chrome'`), CSS biasa dengan token. Tanpa kerangka UI.

**Spec:** `docs/superpowers/specs/2026-11-14-revisi-bo-3-design.md` (matriks keterlacakan I1 sampai N1 ada di bagian 5; keputusan bagian 6).

## Global Constraints

- CSP `style-src 'self'`: tanpa atribut `style` dan tanpa `innerHTML`; lebar dinamis lewat `element.style.setProperty` atau atribut SVG.
- Anggaran JS awal 70 KB gzip dan CSS 25 KB gzip per aplikasi (`npm run budget`); POS sekarang 69,50 KB sehingga **tidak boleh menambah apa pun ke `src/shared/labels/*` atau `src/shared/messages.ts`**. Layar Transaksi baru dimuat malas lewat `import()`.
- Teks tanpa tanda pisah en dan em (`npm run lint:teks`), termasuk berkas teks dan tes.
- Target sentuh 48 px pada tombol utama; axe WCAG A dan AA nol pelanggaran di semua rute BO terang dan gelap; kontras `npm run kontras` nol gagal.
- Layar tanpa scroll halaman pada 1366x640, 1280x640, 1280x720, 1366x768, 1920x1080, dan tabel barang minimal tiga baris tampak pada 1280x640.
- Harga beli akhir, HPP, dan riwayat harga beli hanya untuk Owner: kolom HARGA pada riwayat Pembelian (Info barang) dan blok Harga Histori Beli pada dialog Rincian Barang disembunyikan untuk Supervisor. Supervisor berhak atas BO-08 dan BO-09 (buat PO, terima barang), sehingga harga yang ia ketik sendiri pada faktur pembelian dan PO tetap tampil.
- Setiap layar tetap mengembalikan `ScreenHandle { element, destroy }`; kelas akar halaman tetap `bo-form-page` (dipakai tes lama).
- Server dev membuang CSP: ukur dan e2e hanya terhadap `npm run build` lalu `vite preview --port 4173` (preview latar sudah berjalan di 127.0.0.1:4173; bangun ulang setelah tiap perubahan kode sebelum e2e).
- Jangan menyentuh layar Mutasi Stok, Hutang Piutang, Akuntansi, Laporan, Pengaturan (kecuali penghapusan rekening dari Master). Berkas CSS baru dimuat malas bersama layar Transaksi; `bo-fit.css` tidak diubah kecuali dicatat di tugas terkait.
- Perintah di Git Bash: awali rute dengan `MSYS_NO_PATHCONV=1`. Tulis skrip Python lewat berkas, bukan heredoc.

## Review Focus

1. Barang tanpa riwayat pada rentang terpilih: setiap tab Info menampilkan pesan kosong, bukan tabel rusak atau galat (Task 1, Task 2).
2. Supervisor melihat kolom HARGA riwayat Pembelian atau blok Harga Histori Beli: tidak boleh ada angka itu di DOM mereka, sementara harga yang ia ketik sendiri pada faktur pembelian tetap tampil (Task 2, Task 4, Task 7).
3. Kuantitas 0, negatif, atau desimal pada barang bilangan bulat, dan diskon melebihi harga: Lanjut ditolak dengan pesan, total tidak pernah negatif (Task 4).
4. Menyimpan PO atau SO tanpa pemasok atau pelanggan atau tanpa baris barang: ditolak dengan pesan, store tidak berubah (Task 8).
5. Nama barang, pelanggan, atau keterangan sangat panjang dan 30 baris: halaman tidak menggulir, tabel menggulir di dalam, teks terpotong rapi dengan elipsis (Task 3, Task 10).
